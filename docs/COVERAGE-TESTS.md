# Ручные тесты охвата `sysproxy`

Строки «Ловится» и «Не ловится» в [LIMITATIONS.md](LIMITATIONS.md) становятся
фактом только после строки в этой матрице. До замера это **ожидание**, и в
LIMITATIONS оно так и помечается. Не угадываем, что пройдёт мимо, — меряем.

Системный слой юнит-тестами не покрыть (требуется реальное окружение ОС), поэтому
это ручной прогон перед закрытием фазы и после изменений в `sysproxy`
или `engine`.

## Как прогонять

1. `gostpx off`. Записать реальный IP: https://ifconfig.me в браузере.
2. `gostpx on` в отдельном окне, оставить работать.
3. Каждую строку матрицы выполнить при `on`. Сравнить результат
   с IP прокси и с реальным IP.
4. Строки, где результат зависит от прокси, повторить при `off` —
   убедиться, что ответ меняется (иначе тест ничего не доказал).
5. Заполнить «Результат»: `✅ прокси` / `⚠ мимо` / `✗ не работает`,
   дата, версия (`gostpx --version`), версия ОС.
6. Перенести итог в LIMITATIONS: подтверждённое — в «Проверено руками»,
   опровергнутое ожидание — исправить.

Легенда ожидания: **П** — ждём через прокси, **М** — ждём мимо.

### Куда подключается процесс

Для программ, которые не показывают IP. Если все TCP-соединения процесса
идут на `127.0.0.1:8080`/`:1080` — он в прокси; внешние адреса — мимо.

```powershell
Get-NetTCPConnection -OwningProcess (Get-Process Telegram).Id |
  Select-Object RemoteAddress, RemotePort, State
```
