# Платформенные заметки

Собранные при исследовании факты, которые определяют реализацию.
Всё, что здесь написано, влияет на код — это не справочник, а список ограничений.

---

## macOS

### Системный прокси без запроса пароля

`networksetup` несёт приватный entitlement на право
`system.services.systemconfiguration.network`, поэтому администратору он
меняет настройки **без запроса пароля**. Прямой вызов
`SCPreferencesCreateWithAuthorization` из приложения, наоборот, будет
спрашивать авторизацию при каждом изменении.

**Следствие:** режим `sysproxy` реализуется вызовом `networksetup`, а не
через SystemConfiguration API. Это тот же путь, что в старом скрипте, и это
правильный путь.

**Оговорка:** если в системе включено «Требовать пароль администратора для
доступа к общесистемным настройкам», пароль всё-таки запросится. Обработать
как штатную ошибку с внятным сообщением.

### Активный сетевой сервис

Прокси задаётся не системе, а конкретному сетевому сервису («Wi-Fi»,
«Ethernet»). Старый скрипт определяет сервис один раз и на этом
останавливается — при переключении Wi-Fi ↔ Ethernet настройка остаётся
на старом интерфейсе.

Правильно: определять сервис по устройству из `route -n get default`,
переприменять при каждом событии смены сети, а при выключении — снимать
прокси со **всех** сервисов, которым он был проставлен, а не только с текущего.

### TUN

`utun` создаётся через `wireguard-go`, требует root. Отсюда демон.

### Привилегированный демон без подписи

`SMAppService` требует подписанного бандла с Developer ID — для этого проекта
недоступно (ADR-005). Используется LaunchDaemon-plist в
`/Library/LaunchDaemons/`, устанавливаемый разовым
`osascript -e 'do shell script "..." with administrator privileges'`.

### Gatekeeper

Без нотаризации первый запуск блокируется. В старом скрипте это обходилось
`xattr -cr` и `codesign --force --deep --sign -` — для своего бинаря это
приемлемо, для чужого приложения (SwiftBar) это ломало его автообновление
и делать так не следует.

### Архитектуры

Целевые архитектуры macOS: Apple Silicon (arm64) и Intel (x86_64). Собирать
universal binary через `lipo`, тестировать обе ветки.

## Windows

### Системный прокси живёт в HKCU

`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings`,
изменения применяются вызовом
`InternetSetOption(INTERNET_OPTION_PROXY_SETTINGS_CHANGED)` и
`INTERNET_OPTION_REFRESH`.

Это **пользовательский** куст. Демон работает как `LocalSystem` и напишет
не туда. Поэтому запись выполняет UI-процесс (ADR-016).

### Охват системного прокси заметно хуже, чем на macOS

- WinINET читают IE/Edge/Chrome и старые приложения;
- WinHTTP, .NET и `System.Net` его **не** читают — у них своя конфигурация;
- приложения со своим сетевым стеком (Go, Java, многие игры, часть мессенджеров)
  игнорируют оба;
- **SOCKS5 на системном уровне Windows не поддерживается вовсе**, тем более
  с авторизацией.

**Следствие:** режим `sysproxy` на Windows — это HTTP-прокси на localhost,
через который движок уже ходит в SOCKS5-апстрим. И даже так он покрывает
меньше приложений, чем на macOS. TUN на Windows не опция, а основной режим.

### Wintun

Драйвер поставляется как `wintun.dll` с встроенным драйвером внутри —
встраивается в бинарь через `go:embed` и распаковывается при первом запуске.
Создание адаптера и правка маршрутов требуют прав администратора.

Два пути: манифест `requireAdministrator` у всего приложения (UAC при каждом
запуске) или служба + UAC только при установке. Выбран второй (ADR-005) —
иначе UAC будет всплывать постоянно, что убивает идею «быстрого переключения».

### Named pipe

`\\.\pipe\gostpx` с DACL, разрешающим доступ только SID установившего
пользователя. Пайп без ACL, за которым стоит SYSTEM-служба, умеющая
подключаться куда угодно, — это дыра.

## Сборка

Wails требует CGO и WebView2, кросс-компиляция macOS → Windows не работает.
Релизы собираются в GitHub Actions на раннерах обеих платформ; артефакты
скачиваются из Actions, подписи нет.
