# План разработки

Принцип: рабочий тул после первой фазы, дальше — наращивание.
Оценки в неделях при неполной занятости; это ориентир, не обязательство.

Исследование аналогов, выбор стека, архитектура, ADR-001…008, схема конфига,
спецификация охвата трафика. Результат — содержимое `docs/`.

## Phase 1 — Ядро и CLI ✔ выполнена

Платформенно-нейтральное ядро плюс системный прокси той платформы, на которой
ведётся работа. GUI пока нет вовсе — и это сознательно: ядро отлаживается
командами, к моменту подключения Wails уже есть работающий тул.

- [x] Каркас репозитория, `go.mod`, раскладка пакетов
- [x] `internal/config` — схема TOML, загрузка, валидация с номерами строк,
      дефолты, терпимость к UTF-8 BOM
- [x] Разделение `config.toml` и `state.json` — приложение не переписывает
      конфиг при обычной работе (ADR-007)
- [x] Горячая перезагрузка по `fsnotify` с откатом на старый конфиг при ошибке
- [x] `internal/secrets` — поверх `zalando/go-keyring`: Keychain на macOS,
      Credential Manager на Windows; один API на обе платформы
      _(заменено в Phase 2 файлом `credentials.toml`, [ADR-011](DECISIONS.md#adr-011))_
- [x] `internal/engine` — outbound через `proxy.Proxy` из `tun2socks`,
      ingress: локальные HTTP CONNECT и SOCKS5
- [x] `internal/sysproxy` — реализация для своей платформы
- [x] `internal/cli` — `on|off|toggle|mode|status|set|dns|test|config *`,
      коды возврата, `--json`
- [x] Событийная смена статуса при обрыве (ARCHITECTURE.md §7)

Всё в одном процессе, демона ещё нет.

**Готово, когда:**
`gostpx set socks5://...` → `gostpx on` → трафик браузера идёт через прокси;
`gostpx status` честно показывает охват режима `sysproxy`; правка
`config.toml` в редакторе подхватывается на лету; сломанный конфиг не
применяется и не роняет соединение; пароль лежит в системном хранилище,
а не в файле.

**Готово, когда:** коллега скачивает артефакт из Actions и пользуется на своей

**Важно:** здесь выясняется реальный охват `sysproxy` на Windows. Ожидание —

вовсе. Результат заносится в [LIMITATIONS.md](LIMITATIONS.md) фактами, а не
предположениями, и становится аргументом за Phase 3 — критерий пересмотра
в [ADR-017](DECISIONS.md#adr-017).

## Phase 3 — Демон и TUN на macOS (~2–3 нед) — ОТЛОЖЕНА

> **Отложена [ADR-017](DECISIONS.md#adr-017) (2026-09-28).** Охват расширяется
> внутри `sysproxy` (явный прокси на локальных слушателях, `gostpx env`,
> рецепты для программ). Критерий возврата — нужная программа подтверждённо
> не ловится (COVERAGE-TESTS M14/W17 и далее).

Самая тяжёлая фаза. Демон нужен только режиму `tun`, `sysproxy` остаётся без демона ([ADR-016](DECISIONS.md#adr-016)).

- [ ] `cmd/gostpxd` — демон, жизненный цикл, логи, root-owned state-файл
- [ ] `internal/ipc` — JSON-RPC поверх unix-сокета, проверка UID пира
- [ ] Установка LaunchDaemon по явному действию («Включить TUN…»), разовый запрос пароля; удаление так же явно
- [ ] Движок `internal/engine` в демоне для `tun`; `sysproxy` остаётся в UI-процессе (ADR-016); взаимоисключение сессий UI и демона
- [ ] Вернуть `tun2socks` — **только** как TUN-ingress и gVisor-стек;
      `proxy.Proxy` реализовать поверх `DirectDialer` (ADR-010)
- [ ] `internal/tun` — utun, `tun2socks.engine`, MTU по умолчанию
- [ ] Pin-route `/32` до IP прокси через исходный шлюз (ARCHITECTURE.md §6.1)
- [ ] `internal/dns` — локальный DoH-форвардер, порт 53 из TUN в него
- [ ] Корректный teardown при остановке и при аварийном падении демона
- [ ] Определение рабочего IPv6 в сети → предупреждение в статусе

**Готово, когда:** `curl` без переменных окружения, `dig`, UDP-трафик и
приложение, игнорирующее системный прокси, — все идут через прокси; IPv6,
если он есть, честно помечен как идущий мимо.

## Phase 5 — Смена сети и индикация (~1 нед)

Раньше эта фаза называлась «надёжность» и включала kill-switch, bypass-движок
и защиту от утечек. После [ADR-008](DECISIONS.md#adr-008) от неё осталось
следующее:

- [ ] `internal/netwatch`: `SCDynamicStore` на macOS, `NotifyRouteChange2`
      на Windows; переустановка маршрутов при смене сети и выходе из сна
- [ ] Переприменение `sysproxy` к новому активному сетевому сервису
- [ ] `gostpx doctor` — проверка окружения и сбор диагностики
- [ ] Внятные ошибки в UI вместо тишины
- [ ] Сверка фактического охвата с [LIMITATIONS.md](LIMITATIONS.md) —
      документ нормативный, расхождение считается багом

**Готово, когда:** ноутбук переключается Wi-Fi → Ethernet, уходит в сон и
возвращается — туннель жив; при обрыве статус краснеет немедленно.

## Что осознанно не делаем

- Kill-switch, bypass-листы, заворачивание IPv6, выбор схемы DNS —
  [ADR-008](DECISIONS.md#adr-008)
- Несколько прокси, профили, автоматический failover и балансировка —
  [ADR-012](DECISIONS.md#adr-012)
- Shadowsocks и WireGuard — [ADR-010](DECISIONS.md#adr-010); фаза
  «Протоколы» убрана из плана целиком, ssh уже работает
- Правила маршрутизации по приложениям и процессам — это Proxifier/ProxyBridge,
  прямо исключено из задачи
- Подписки, geoip-базы, наборы правил — это Clash-клиенты
- VLESS / VMess / Reality / Hysteria — потребовали бы сменить ядро на
  sing-box или mihomo и утащить GPL-3.0 (ADR-002)
- Мобильные платформы
