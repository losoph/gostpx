# Конфигурация

**Конфиг-файл — источник истины.** Приложение можно не открывать вовсе:
всё настраивается текстовым редактором и командной строкой. GUI — надстройка,
а не единственный путь. Обоснование — [ADR-007](DECISIONS.md#adr-007).

---

## 1. Формат: TOML

Секции как в INI, но с комментариями и без чувствительности к отступам.
Правится в Notepad, `vi` или чём угодно без риска сломать структуру пробелом.

Парсер обязан терпеть **UTF-8 BOM** — Notepad на Windows его иногда дописывает.

## 2. Расположение

| | macOS | Windows |
|---|---|---|
| Конфиг | `~/Library/Application Support/gostpx/config.toml` | `%APPDATA%\gostpx\config.toml` |
| Состояние | `~/Library/Application Support/gostpx/state.json` | `%APPDATA%\gostpx\state.json` |
| Конфиг демона | `/Library/Application Support/gostpx/daemon.toml` (root, 0600) | `%ProgramData%\gostpx\daemon.toml` (SYSTEM) |
| Логи | `~/Library/Logs/gostpx/` и `/var/log/gostpx/` | `%ProgramData%\gostpx\logs\` |

Путь печатает `gostpx config path`, открывает в редакторе — `gostpx config edit`.

## 3. Разделение config.toml и state.json

Приложение **не переписывает конфиг при обычной работе** — иначе комментарии
и форматирование, ради которых всё затевалось, проживут до первого клика в меню.

| | `config.toml` | `state.json` |
|---|---|---|
| Кто пишет | человек; GUI — только при явном редактировании | только приложение |
| Что лежит | прокси, режим по умолчанию, DNS, интервалы | текущий режим, факт активной сессии, кеш внешнего IP |
| Комментарии | сохраняются | не применимо |

Переключение режима из меню трогает только `state.json`.

## 4. Полный config.toml

Конфиг целиком — он маленький, и это сознательно. Один прокси, без списка
профилей, без bypass-листов, без kill-switch.

```toml
version = 1

# Режим по умолчанию при старте.
#   sysproxy — только приложения, уважающие системный прокси (по умолчанию)
#   tun      — весь IPv4-трафик системы (появится в Phase 3, ADR-016)
#   off      — не подключаться
mode = "sysproxy"

autostart   = false   # запускать приложение при входе в систему (по умолчанию false, ADR-014)
autoconnect = true    # подключаться сразу при запуске

# ── Прокси-сервер ─────────────────────────────────────────

[proxy]
type   = "socks5"              # socks5 | http | ssh
host   = "proxy.example.net"
port   = 8000
user   = "username"
# пароля здесь нет — он в credentials.toml рядом (§6, ADR-011)

# ── DNS ───────────────────────────────────────────────────
# Применяется только в режиме tun. В режиме sysproxy имена резолвит
# сам прокси-сервер, и эта секция не используется — см. LIMITATIONS.md.

[dns]
doh = "https://dns.google/dns-query"

# ── Режим system proxy ────────────────────────────────────

[sysproxy]
http_listen  = "127.0.0.1:8080"
socks_listen = "127.0.0.1:1080"

# ── Проверка состояния ────────────────────────────────────

[health]
probe_interval = "60s"   # TCP-connect до прокси, без ICMP

[log]
level = "info"           # debug | info | warn | error

[ui]
# false — поля настроек в GUI становятся только для чтения.
config_writable = true
```

### Чего в конфиге нет и почему

| | |
|---|---|
| `[[profiles]]` | профиль один; список не нужен |
| `bypass` | не нужен: локальная сеть и так идёт по connected-маршрутам, которые специфичнее default через TUN, а в режиме `sysproxy` остаются системные исключения по умолчанию |
| `killswitch` | при обрыве трафик идёт напрямую, и это честно показывается в трее — [LIMITATIONS.md](LIMITATIONS.md#поведение-при-обрыве) |
| `ipv6` | IPv6 в туннель не заворачивается; последствия описаны в [LIMITATIONS.md](LIMITATIONS.md#ipv6--отдельно) |
| `mtu` | берётся значение по умолчанию из библиотеки |
| `dns_mode` | всегда DoH; выбор режима убран |

Маршрут `/32` до IP прокси-сервера в конфиге тоже отсутствует — он не
настройка, а физическая необходимость: без него TUN замыкает трафик до
самого прокси сам на себя. Демон ставит его сам и снимает при отключении.

## 5. Правка руками

```bash
gostpx config edit        # открыть в $VISUAL / $EDITOR, на Windows — notepad
gostpx config validate    # проверить, ничего не применяя
gostpx config show        # эффективный конфиг после подстановки дефолтов
```

**Горячая перезагрузка.** Приложение следит за файлом. После сохранения:

1. файл читается и валидируется;
2. если всё в порядке — новые настройки применяются, в трее короткое
   уведомление «конфиг перечитан»;
3. если есть ошибка — **старый конфиг продолжает работать**, а в трее
   появляется значок ошибки с номером строки.

Без разрыва применяются `[dns]`, `[health]`, `[log]`, `[ui]`. Смена `mode`
и `[proxy]` требует пересоздания сессии — это делается явно, чтобы сохранение
файла не рвало трафик неожиданно.

## 6. Пароль

Пароль прокси лежит в отдельном файле `credentials.toml` в той же папке,
что и `config.toml` ([ADR-011](DECISIONS.md#adr-011)):

```toml
# gostpx: пароль прокси (ADR-011). Не пересылать и не коммитить.
password = "..."
```

- права `0600`; более широкие при чтении ужимаются;
- файл пишет `gostpx set`; URL без пароля файл удаляет;
- нет файла — нет пароля, авторизация только по `user` или без неё;
- системное хранилище (Keychain / Credential Manager) не используется.

`config.toml` секретов не содержит — его можно показывать и пересылать.
Поле `proxy.secret` из старых версий устарело: парсится, игнорируется,
`config validate` предупреждает с номером строки.

Демон пароль с диска не читает — его передаёт UI при подключении
([ARCHITECTURE.md §4](ARCHITECTURE.md#4-секреты-не-хранятся-в-демоне)).

## 7. Задать прокси одной строкой

```bash
gostpx set socks5://user:pass@proxy.example.net:8000
```

Пароль уезжает в `credentials.toml`, в `config.toml` — только
тип, хост, порт и пользователь.
Поддерживаются `socks5://`, `http://` и `ssh://` — три протокола
([ADR-010](DECISIONS.md#adr-010)).

Для `ssh://` ключ хоста должен быть в `~/.ssh/known_hosts`: проверка ключа
обязательна. Если сервера там нет, подключись к нему обычным `ssh` один раз —
тул намеренно не доверяет незнакомым ключам молча.
